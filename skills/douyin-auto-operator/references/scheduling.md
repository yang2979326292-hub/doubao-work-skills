## 1. 两个任务的分工

| 任务 | cron 表达式 | 职责 |
|---|---|---|
| 每日汇报与备稿 | `0 22 * * *` | 读取当日真实数据并汇报；制作次日完整内容并存为草稿（含 BGM） |
| 每日发布 | `0 20 * * *` | 打开当天草稿，核对无误后在 20:00 发布 |

两者均 `runtime_type=1`（云端）、`schedule_type=cron`、时区 `Asia/Shanghai`。发布与备稿时间应从配置 `schedule` 读取，用户改时间就改这里和 cron 表达式。

## 2. 创建步骤

1. 先 `get_current_time`（用户时区）锚定当前时间，判断首次触发是今天还是明天。
2. 用 `create_cron_job` 分别创建两个任务；query 开头必须写"本次请求是由「{title}」定时任务到时触发的"。
3. 创建后再次 `get_current_time` 校验首次触发关系；修改已有任务前先 `get_cron_job` 取回完整详情，只改用户要求的字段。
4. 不要把密码、cookie、验证码写进 query。

## 3. 备稿任务 query 模板

> 把【】内替换为配置的实际值；路径同时给出本地与云主机两套。

```text
本次请求是由「【备稿任务标题】」定时任务到时触发的。
【任务目标】运营账号【昵称】（抖音号【抖音号】），当前阶段目标【goal.primary】。
定位与形式：【视觉风格】+【内容母题】，横屏【画幅】+ ≤950 字长文案 + 5 话题 + 热门榜 BGM。
【执行步骤】
1) 打开创作者中心，异常视口用 Emulation.setDeviceMetricsOverride 恢复；登录失效则请用户处理。
2) 读取今日作品真实数据，按 benchmark 计算点赞率/划走率并与历史对比。
3) 数据与复盘追加写入运营日志，输出简洁汇报。
4) 按 topics 加权轮换制作次日内容：图 + 文案 + 5 真实话题 + 热门榜 BGM，保存为草稿。
5) 定期用视频提取能力学习同赛道高赞作品，沉淀要素并经自家数据验证。
【路径】本地：【Windows 项目根】；云主机：【Linux 项目根】。
【纪律】数据只来自真实页面，禁止杜撰；用户最新口头指令优先。
```

## 4. 发布任务 query 模板

```text
本次请求是由「【发布任务标题】」定时任务到时触发的。
【目标】在【publish_time】发布当天已备好的草稿（账号【昵称】）。
【发布前核对】横屏图已上传；正文 ≤950 字且结尾完整；5 个可点击话题；BGM 已绑定且符合意境；
"谁可以看"为公开（对 input.radio-native 执行 .click()）。
【发布】核对无误点"发布"；触发安全验证则 interaction.request_action 请用户完成。
【验证】内容管理页确认"已发布"、作品数 +1，输出发布结果。
【异常】登录失效请用户重新登录；草稿缺失或不合格则不擅自发布，如实说明缺什么。
```

## 5. 时间校验与注意事项

- 当下游动作涉及"现在/今天/明天"等相对时间，必须先 `get_current_time`，禁止凭记忆推断。
- 若首次触发时间已过，应告知用户并立即执行一次，而不是等下一天。
- 平台显示的下次运行时间可能因错峰调度略有提前（高峰期常见），cron 表达式仍以设定时间为准，实际以触发为准。
- 若用户要求的多个时间点动作不同（如 20:00 发布、22:00 备稿），用两个独立 cron，不要强行合并成一条。

# 架构与设计说明

## 模块

- `ClientSkin.cs`：Windows原生设置窗口、本地导入、颜色/底色/不透明度、配置原子保存、首次启用和状态展示。
- `SkinLauncher.cs`：固定入口启动；检测已有客户端、选择回环端口、启动皮肤宿主、等待真实应用状态，不强制结束工作任务。
- `client-info.ps1`：定位主进程/标准安装路径，检查端口所属进程及仅回环监听。
- `cdp.mjs`：发现内部page target、拒绝网页/后台、WebSocket会话、命令超时与1MiB单消息上限。
- `media-transfer.mjs`：384KiB块读取、base64分块发送、累计字节校验、完整长度确认与失败取消。
- `renderer.mjs`：内部协议和布局二次检查、暂存Blob、单个背景媒体、循环静音、可见性暂停、释放资源。
- `theme.mjs`：配置归一化、颜色格式与媒体文件名验证、CSS生成、前景对比色。
- `regions.mjs`：三栏表面与嵌套透明、动态区域合并更新、最终全部侧栏继承底色和导航渐变修复。
- `worker-lock.mjs`：每个data目录一个宿主，正常释放或确认旧PID不存在后处理失效锁。
- `shortcut-installer.ps1`：精确匹配桌面和开始菜单官方入口，先备份、后更新、回读；恢复时拒绝覆盖后来用户的修改。

## 数据流

本机导入 → 插件data/media副本 → settings.json保存相对文件名 → 宿主归一化 → 确认客户端端口归属 → 主窗口内部协议/布局校验 → 分块媒体 → 页面Blob → CSS单层表面 → 真实状态回读。

文件不上云。分发包无data，首次保存时创建。状态权威来源为插件status.json对应的实际客户端核验；过期状态不能用于认定现在已生效。

## 透明度设计

用RGBA底色，不对整个聊天区域设置opacity。外层主工作表面用同一个颜色/alpha，消息/输入等嵌套容器透明以免叠加，文字不变透明。

最初仅检查表面alpha不足以保证视觉一致：后代的`bg-inherit`仍会重复绘制RGBA。最终规则定向覆盖`[data-testid="flow_chat_sidebar"] div.bg-inherit`，不清除活动会话链接和悬停高亮。

导航条遮罩是独立的黑色background-image渐变，需单独移除，不能只调整background-color。

## 性能策略

- 已存在的背景不重复传输；切换时释放旧Blob和媒体元素。
- 无变化不重写主要CSS，复用CDP会话。
- 稳态宿主轮询约10秒，目标发现约30秒；DOM区域更新合并到1秒。
- 侧栏完整修复只用范围化CSS，不新增observer或播放器。
- 连续媒体失败停止重试，避免压垮客户端。
- 页面隐藏时暂停视频。只有短时播放与状态采样，不宣称所有交互都不卡。

## 自动恢复

临时页面注入会在退出后消失。因此通过外置启动器固定启动参数和宿主启动，而不是篡改客户端安装文件或原生设置。仅用户确认的桌面/开始菜单入口被替换，恢复有备份。关闭设置窗口不停止宿主；退出客户端后宿主自行停止。

启动动画不是最终产品需求，已移除运行依赖，旧源码只留本机历史备份。旧`--startup`参数即使被历史入口传入，也不再产生动画调用。

## 安全限制与可维护性

调试接口能力大于换肤所需权限，因此必须仅回环、核对进程路径、拒绝其他target。不得把端口公开、读取账号凭据或自动注入任意网站。媒体使用本机随机文件名和白名单格式，阻止路径穿越；颜色限定六位十六进制，避免CSS文本注入。

内部选择器不是官方稳定API。适配失败时应报告而非把旧测试当成功；升级客户端后应重新验证。程序当前未签名，启动前应审阅来源和校验文件。

# douyin-auto-operator 使用说明书

把一个抖音账号交给豆包工作，按你设定的方向自动或半自动运营：每天读取创作者中心的真实数据做复盘，提前做好第二天的图文并存成草稿，到点检查后发布。账号定位、内容主题、画面风格、文案规范、BGM 和发布时间，都写在一个配置文件里，改配置就能换成你自己的运营方案。

- 适合：想用 AI 稳定日更的个人号、新号起步、故事型或知识型 AIGC 图文账号（例如历史人文、未来星际）。
- 不适合：真人出镜视频、直播、带货挂车、私信和评论区的自动回复、多账号矩阵批量操作。

## 1. 下载与安装

**下载链接**

- 整个合集（ZIP）：https://codeload.github.com/yang2979326292-hub/doubao-work-skills/zip/refs/heads/main
- 在 GitHub 上查看这个 skill 的文件：https://github.com/yang2979326292-hub/doubao-work-skills/tree/main/skills/douyin-auto-operator

**方法一：让豆包工作帮你装（推荐）**

在豆包工作里直接说：

> 帮我把 https://github.com/yang2979326292-hub/doubao-work-skills 里的 douyin-auto-operator 安装到我的豆包工作用户 skill 目录

**方法二：手动安装**

1. 用上面的链接下载 ZIP 并解压，进入 `doubao-work-skills-main\skills\`。
2. 把整个 `douyin-auto-operator` 文件夹复制到豆包工作的用户 skill 目录（在文件资源管理器地址栏粘贴即可打开）：

   ```
   %LOCALAPPDATA%\DoubaoWork\User Data\Default\.doubaowork\agent_mode\workspace\.user_skills\
   ```

3. 新开一个对话，说“用 douyin-auto-operator 帮我运营抖音账号”，确认它被调用。

放进这个目录的 skill 会自动同步到豆包工作的云主机，电脑和云主机两边都能用。

## 2. 使用前准备

| 项目 | 要求 | 说明 |
|---|---|---|
| 抖音账号 | 必需 | 能在浏览器里登录 [抖音创作者中心](https://creator.douyin.com/)。首次登录、扫码和短信验证必须你本人完成。 |
| 豆包工作 | 必需 | 用它的浏览器能力操作网页、用图片生成能力做配图、用定时任务能力每天自动执行。 |
| Python 3 | 可选 | 只给指标计算脚本用，只用标准库。豆包工作在电脑和云主机上都自带。没有 Python 时，豆包工作会按公式手算，不影响运营。 |
| 运营方向 | 建议先想好 | 账号讲什么、给谁看、多久更新一次。想不好也可以先用默认的“历史人文 + 未来星际”跑起来，再按数据调整。 |

## 3. 五分钟上手

1. **准备配置文件**：把 skill 里的 `assets/operator-config.yaml` 复制到你在豆包工作里用的项目文件夹，至少填写三项：

   ```yaml
   account:
     nickname: "你的账号昵称"
     douyin_id: "你的抖音号"
   goal:
     primary: "followers"     # followers 涨粉 / traffic 流量 / monetize 变现
   ```

   不想手动改文件，也可以直接告诉豆包工作“我的账号叫××，抖音号××，先以涨粉为主”，让它帮你填。
2. **登录**：在豆包工作里说“打开抖音创作者中心”，按提示扫码登录。
3. **先跑一条**：说“按配置做一条明天要发的图文，先发给我看”。第一次建议先审稿，确认画面、文案和 BGM 都符合你的预期。
4. **设置定时**：说“每天 20:00 发布，前一天 22:00 汇报数据并备好第二天的草稿”。豆包工作会建两个定时任务。
5. **看汇报**：之后每天 22:00 会收到当天数据和第二天的内容计划。想改方向，直接说，或者改配置文件。

## 4. 它每天做什么

默认节奏如下（时间可在配置里改）：

```
前一天 22:00  汇报与备稿
  1. 打开创作者中心，确认登录状态
  2. 读取当天作品的真实数据（播放、点赞、评论、分享、收藏、划走率、涨粉）
  3. 计算点赞率等指标，和历史、阈值对比，写进运营日志并汇报
  4. 按主题轮换做第二天的内容：横屏氛围图 + 950 字以内长文案 + 5 个话题 + 热门榜 BGM
  5. 存成草稿

当天 20:00  发布
  1. 打开前一晚的草稿，逐项核对：图片、正文结尾完整、5 个可点击话题、BGM、可见范围“公开”
  2. 全部合格才点发布；遇到扫码或短信验证就停下，请你本人处理
  3. 到内容管理页确认“已发布”，再汇报结果
```

**先审稿还是直接发**：由配置里的 `workflow.review_before_publish` 决定。

- `true`：每条先发给你审，你确认后才发布。适合刚开始、或者对内容要求严格的阶段。
- `false`：到点自动发布。你仍然可以在发布前任何时候查看草稿、要求修改或叫停。

**一条合格图文的标准**：16:9 横屏氛围图 + 正文 950 字以内且结尾完整 + 恰好 5 个可点击的真实话题 + 从热门榜选的 BGM + 可见范围公开。缺任何一项都不会发布。

## 5. 配置文件逐项说明

配置文件是 `operator-config.yaml`。豆包工作每次运营前先读你项目文件夹里的这份；找不到时用 skill 自带的默认模板。你在对话里说的最新要求优先于配置文件，豆包工作会顺手把改动写回配置，保持两边一致。

### 5.1 account：账号信息

| 字段 | 必填 | 含义 |
|---|---|---|
| `nickname` | 是 | 账号昵称 |
| `douyin_id` | 是 | 抖音号 |
| `homepage_bio` | 否 | 主页简介，建议写清“关注你能得到什么” |
| `creator_center` | 否 | 创作者中心地址，一般不用改 |

### 5.2 goal：阶段目标

| 字段 | 默认 | 含义 |
|---|---|---|
| `primary` | `followers` | `followers` 涨粉优先：强化关注理由和系列感；`traffic` 流量优先：强化开头钩子和话题；`monetize` 变现优先：在有粉丝基础后调整内容和转化路径 |
| `phase_weeks` | 4 | 当前阶段持续几周，到期后建议复盘再定下一阶段 |
| `benchmark.like_rate_good` | 3.0 | 点赞率合格线（%） |
| `benchmark.like_rate_great` | 5.0 | 点赞率优质线（%） |
| `benchmark.swipe_healthy` | 55.0 | 划走率健康线（%），低于它算健康 |

### 5.3 topics：内容主题（决定账号讲什么）

可以写任意多个主题，每个主题单独设置：

| 字段 | 含义 |
|---|---|
| `name` | 主题名称 |
| `enabled` | 是否参与排期，`false` 就暂停这个主题 |
| `weight` | 权重，越大出现得越频繁 |
| `subject` | 选题方向 |
| `angle` | 切入角度 |
| `structure` | 文案骨架，按顺序写几段 |
| `ending` | 结尾落点 |
| `sources` | 资料来源要求 |

排期规则：按权重轮换，同一主题最多连续出现 2 次。

示例：把账号改成“城市夜景故事”，再加一个“书法与汉字”主题、出现频率更低：

```yaml
topics:
  - name: "城市夜景"
    enabled: true
    weight: 2
    subject: "一座城市在夜里的普通人故事"
    angle: "从一盏灯、一条街切入，讲城市里的人"
    structure:
      - "强钩子：一个反常识的夜景细节"
      - "人物与场景：时间、地点、一个具体的人"
      - "情绪转折"
      - "落点：回到每个在城市里奔波的人"
    ending: "给读者陪伴感"
    sources: ["城市历史资料", "公开报道"]
  - name: "书法与汉字"
    enabled: true
    weight: 1
    subject: "一个汉字或一幅名帖背后的故事"
    angle: "从字形演变讲到人生"
    structure:
      - "强钩子：这个字原来是这个意思"
      - "字源与名帖出处"
      - "书写者的经历"
      - "落点：今天的我们能从中得到什么"
    ending: "引导读者在评论区写下自己喜欢的字"
    sources: ["说文解字", "书法史资料"]
```

### 5.4 visual：画面风格

| 字段 | 默认 | 含义 |
|---|---|---|
| `aspect_ratio` | `16:9` | 画幅。改成 `9:16` 或 `1:1` 时要同步改 `resolution` |
| `resolution` | `2730x1536` | 出图尺寸 |
| `style_keywords` | 电影化写实、宏大对称构图等 | 直接决定配图的生成提示词，按喜好增删 |
| `color_tone` | 冷青基调 + 暖光点缀 | 整体色调 |
| `image_count` | 1 | 每条图文的图片数。实测 1 张横屏的话题和排版最稳 |

### 5.5 copywriting：文案规范

| 字段 | 默认 | 含义 |
|---|---|---|
| `max_chars` | 950 | 正文字数上限。描述区硬上限 1000 字，超出会被截断、丢掉结尾，务必留余量 |
| `title_max_chars` | 20 | 标题字数上限 |
| `title_hook_chars` | 7 | 标题前几个字内要有钩子 |
| `tone` | 短句、口语化、有情绪张力 | 语气 |
| `hashtags_count` | 5 | 话题数。实测第 6 个会把第 5 个顶掉，保持 5 个 |
| `default_hashtags` | `["原创"]` | 每条都带的基础话题 |
| `comment_prompt` | true | 结尾加评论引导（评论一直为 0 时打开） |
| `follow_reason` | true | 明确给出关注理由（涨粉为 0 时打开） |

### 5.6 bgm：背景音乐

| 字段 | 默认 | 含义 |
|---|---|---|
| `required` | true | 每条必须配 BGM |
| `pick_method` | `hot_chart` | 从音乐面板「热门榜」里挑，不用关键词搜索 |
| `avoid_obscure` | true | 避开冷门曲 |
| `by_theme` | 历史向用极简钢琴/大提琴，未来向用空灵合成器 | 每个主题的曲风。新增主题时记得在这里加一行，名字和 `topics.name` 一致 |

### 5.7 schedule 和 workflow：发布节奏与流程

| 字段 | 默认 | 含义 |
|---|---|---|
| `schedule.publish_time` | `20:00` | 每天发布时间 |
| `schedule.prep_time` | `22:00` | 前一天备稿时间 |
| `schedule.timezone` | `Asia/Shanghai` | 时区 |
| `schedule.frequency` | `daily` | 更新频率 |
| `workflow.review_before_publish` | false | 是否每条先送审，见第 4 节 |
| `workflow.auto_save_draft` | true | 草稿由平台自动保存 |
| `workflow.user_can_intervene` | true | 发布前你随时可以审核或叫停 |

改了发布或备稿时间后，要让豆包工作同步修改定时任务（说“把发布时间改成每天 19:30”即可），只改配置文件不会自动改已经建好的定时任务。

### 5.8 learning：学习与复盘

| 字段 | 默认 | 含义 |
|---|---|---|
| `study_competitors` | true | 定期学习同赛道高赞作品 |
| `study_items` | 开头钩子、文案结构等 | 学哪些要素 |
| `verify_with_own_data` | true | 学到的东西要用自己账号的数据验证，不照搬 |

## 7. 使用规则（必读）

1. **登录与验证只能你本人操作**。扫码、短信验证码、安全验证出现时，豆包工作会停下来请你处理，不会反复重试，也不会尝试绕过。
2. **数据只来自创作者中心的真实页面**。汇报里的每个数字都能在页面上找到，不编造、不估算。不同页面数字有出入时，以内容管理页为准。
3. **不合格不发布**。草稿缺图、缺 BGM、话题不足 5 个、正文超长被截断、可见范围不是公开，任何一项不满足都不发布，会如实告诉你缺什么，不临时凑内容。
4. **当天没发就说没发**。汇报不会虚报发布结果。
5. **你的最新指令优先**。对话里的新要求覆盖配置文件，豆包工作会把改动写回配置。
6. **AI 内容要主动标识**。2025 年 9 月 1 日起施行的《人工智能生成合成内容标识办法》规定，用户发布 AI 生成合成内容时应当主动声明，并使用平台提供的标识功能进行标识；任何人不得恶意删除、篡改、伪造、隐匿标识。抖音要求在平台注册的账号制作、发布 AI 内容时，使用抖音提供的标识功能主动添加显式标识。本 skill 发布前会勾选“含有 AI 生成内容”。不要要求豆包工作去掉 AI 标识。
7. **内容责任在账号主体**。AI 写的史料、科学概念可能出错，建议在审稿阶段核对关键事实；涉及真实人物、品牌、医疗、金融等内容时更要谨慎。账号的发布内容由账号所有者负责。
8. **遵守平台规则**。不要用它批量刷量、发营销引流内容、搬运他人作品，或在多个账号间重复发布同一内容。
9. **不保存密码和验证码**。定时任务的说明里不会写入任何密码、Cookie 或验证码。

规则 6 的依据：[《人工智能生成合成内容标识办法》全文（国家网信办）](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)、[抖音 AI 内容标识公告报道（人民网）](http://society.people.com.cn/n1/2025/1024/c1008-40588619.html)、[规范短视频内容标注答记者问（国家网信办，2026-05-12）](https://www.cac.gov.cn/2026-05/12/c_1780328273108117.htm)。

## 8. 数据复盘怎么看

**指标和默认阈值**

| 指标 | 算法 | 判断（默认值，可在 `goal.benchmark` 改） |
|---|---|---|
| 点赞率 | 点赞 ÷ 播放 × 100% | ≥5% 优质，≥3% 合格，<3% 不合格 |
| 划走率（2 秒跳出） | 页面直接给出 | <55% 健康，≥55% 偏高 |
| 评论率、分享率、收藏率 | 对应数量 ÷ 播放 × 100% | 跟自己的历史数据比 |

**指标计算脚本**：在 skill 文件夹里运行（数字换成你页面上的真实数据）：

```bash
python scripts/calc_metrics.py --plays 1000 --likes 35 --comments 2 --shares 1 --favorites 6 --swipe 48.5
```

输出：

```json
{
  "like_rate": 3.5,
  "comment_rate": 0.2,
  "share_rate": 0.1,
  "favorite_rate": 0.6,
  "like_judgement": "合格",
  "swipe_judgement": "健康"
}
```

- 自定义阈值：加上 `--like-good 4 --like-great 6 --swipe-healthy 50`。
- 播放为 0 时，比率显示 `null`，判断为“无数据”。
- 查看全部参数：`python scripts/calc_metrics.py --help`。

**数据不好时先改什么**

| 现象 | 优先调整 |
|---|---|
| 划走率高 | 开头三行的钩子和首图 |
| 文案展开率低 | 开头几行的悬念，减少首屏信息量 |
| 点赞率低 | 情绪高点、金句、画面氛围 |
| 评论为 0 | 结尾加开放式提问，或给出可以表态的选择 |
| 涨粉为 0 | 系列化预告、明确的关注理由、主页简介 |

每次只改一两个变量并记下来，才能知道是哪一项起了作用。

## 9. 常见问题

**到点没有发布？**
最常见的原因有三个：前一晚没有备好草稿（找不到草稿时按规则不发布）；登录失效或遇到安全验证，在等你处理；草稿某一项不合格。豆包工作会在那次运行的结果里写明原因。第一次设置定时任务时，如果当晚的备稿任务还没跑过，第二天 20:00 通常会因为没有草稿而不发布。

**发布时间不是整 20:00？**
平台显示的“下次运行时间”可能因为错峰调度提前，例如 19:32。定时规则仍然是你设的时间，以实际触发为准。对发布时间要求严格时，可以让豆包工作在 20:00 前再检查一次。

**换了电脑或改在云主机上运行，又要重新登录？**
云端浏览器和你电脑上的浏览器登录状态不互通，换运行环境后第一次需要重新扫码登录。

**话题输进去了，但发布后不能点击？**
话题必须在编辑器里从候选列表选中、变成可点击状态才算生效；直接粘贴文字不会被识别。skill 里已经写了正确的输入方法，如果平台改版导致失效，告诉豆包工作“话题没有生效，重新检查”。

**BGM 选错了？**
skill 要求选完后回读歌曲名核对。仍然选错时，在审稿阶段指出来，或者开启 `review_before_publish: true`。

**能不能发视频？**
当前流程按“横屏图文”验证过。发视频需要另外调整上传和核对步骤，可以在对话里提出，让豆包工作在这个 skill 的基础上扩展。

**能同时运营多个账号吗？**
一份配置对应一个账号。多个账号需要分别准备配置和定时任务，而且同一个浏览器同一时间只能登录一个账号，不建议用它做批量矩阵。

**平台改版后点不动了？**
SOP 里的按钮选择器来自实测，平台改版后可能失效。豆包工作会先重新识别页面再操作；仍然失败时会停下来说明，不会盲目重试。

---

## 10. 已知限制

- 只支持网页版抖音创作者中心发布图文，不支持手机端、视频、直播。
- 网页操作依赖页面结构，平台改版后可能需要更新 SOP 里的选择器。
- 配图、文案、选曲由 AI 完成，质量会有波动；关键事实请人工核对。
- 定时任务的触发时间以平台实际调度为准，可能和设定时间有几十分钟的偏差。
- 实测情况：图文的上传、话题输入、BGM 绑定、可见范围设置和发布流程在 2026 年 10 月 30 日至 31 日实际跑通过一个新账号；指标脚本在 Windows（Python 3.13）和 Linux 云主机（Python 3.12）上用多组数据测试过，配置模板用 PyYAML 解析通过。其他平台版本和账号类型未测试。
